# The parity checklist — frozen before 06c

**What this is.** `QA.md` records 64 assertions across 12 scenarios, made by driving the *static prototype* in a real browser. This file is that list, frozen, with each assertion rewritten as a claim about an observable of the app at its own route seam. Ticket 15a consumes this file rather than writing it, and every parity test cites a line number here, so a behaviour the suite skips is an unmatched line a reviewer can see rather than a shorter list written to fit the suite.

**Frozen at** commit `cb0564a`. That is the commit this file first appears in, and the one its `13a` criterion numbers belong to: the same commit added the surface-extent criterion to `13a` and moved every criterion after it down by one, so in-thread message search is `13a:22` at this commit and was `13a:21` at `82cc889`. *(This line named `82cc889` when the file was committed — the commit *before* the file existed. Corrected here, in the file rather than in a note, because a freeze record that points one commit early is worse than no record.)* Against `QA.md` (35 lines, sha256 `6920fca428e3dfaf20f7a936627b572ef9ed56dc2d36e9ca1379937c4e060cf5`). The 64 assertion names were read from the recorded run's own machine-readable output (`run-qa.js` → `result.json`: 12 scenarios, 5/5/7/5/5/7/4/6/6/5/7/2 checks). **Do not edit this file to fit what 15a turns out to be able to assert.** If a line cannot be met, that is a finding against the app or the ticket set, not an edit here; reopen 15a or the owning ticket and say so in a comment.

**How to read a line.** Each has four parts:

- **As the prototype asserted it** — `QA.md`'s own claim, quoted or paraphrased from its bullet.
- **As the app must show it** — the same fact as an observable at the app's route seam. Where the prototype's claim names a store, a storage key or its own markup, the rewrite is where the meaning survives without the internal.
- **Ticket · seam** — the ticket whose criteria make the line true (`15a` where the parity suite itself is the only proof), and the seam: **R**oute (a rendered-DOM or browser measurement), **C**ontract (the client interface driven directly), or **N**either.
- **Weakness** — carried from `QA.md`'s own honesty notes or found while transcribing. Omitted where there is none.

**"Line N" means the numbered assertion N, not physical line N of this file.** 15a:15 requires every scenario to cite its line here, and these are the lines it means: the numbering runs 1–64 across the sections, and a citation like `parity-checklist.md` line 64 is the sixty-fourth item, which sits far below the file's sixty-fourth byte-line.

**Two things this file is not.** It is not a new specification: a line added here would be a requirement nobody reviewed. It is also not a summary of `QA.md` — every one of its assertions is below, including the ones the prototype recorded as gaps, because a gap that closes is a parity claim and a gap that survives is a scope decision.

### What `QA.md` turned out to be weaker than it looks about

Recorded here so 15a inherits the caution rather than the claim:

1. **Its overflow method was vacuous** for every document-level assertion (lines 45–50) — `QA.md` admits this at L25. 13a:13 replaces it.
2. **"12 scenarios" is 13 bullets.** `QA.md` L11–23 lists thirteen bullets and L9 says "12 scenarios". The harness merged `Stream pause` and `Paused + "Simulate agent post"` into one scenario (S3), which is why the arithmetic works out to 64 across 12. 15a's criterion and any later reader should cite the *assertions*, not the scenario count.
3. **Its unread counts do not agree with the app's rule.** The prototype's badge excludes the reader's own entries (`app.js` L135); the app counts from `seen` alone (`spec L500`). Three seeded threads give different numbers under the two rules (line 38). A parity test that asserted identical badge counts would contradict the spec.
4. **Its fingerprint was invented.** The prototype's drawer shows a hard-coded string under "Verified identity"; the app derives it (08c). Line 57 asserts the presence of the derived value, not the prototype's.
5. **Its form validation was the browser's.** Line 26's assertion is really a statement that Chrome refused `not-a-url`; the app's validator is its own and its copy is 09's.

### An addition, not a carry-across

Nothing above is new. One behaviour `QA.md` never asserted is worth a separate ticket decision rather than a line here, and it is recorded only so it is not mistaken for parity: **the prototype never asserted what happens to a thread's entries when a permission is revoked mid-read**, which is 11c's subject. It is not in this checklist because the prototype had no permissions at all, and adding it here would have made the definition of done larger than the parity claim it is supposed to measure.
